# grower-service: project guide for Claude

GrowerCare grower registry (ADR-017: its own repository): grower profiles on 128 shard schemas (IN, BR), a phone directory co-located with each grower (SPEC-GRW-01 D1), consent records and phone verification by one-time code (sent through notification-service), and farms (point location, crops). Phone numbers are stored only as HMAC + ciphertext + last 4 digits. It publishes `grower.*` events via the outbox; case-service keeps a replica.

## Conventions
1. **Authorization:** via gc-security (role + geo scope; BU scope does not apply to growers). An out-of-scope grower returns **404**. Never trust client-supplied country or shard: the country comes from the territory.
2. **IDs:** generated by Postgres per shard. Route by decoding them. Serialize IDs as **strings** in JSON.
3. **Events only through the outbox,** with ids only (no names, phones or HMACs).
4. **Country differences** go into reference data (`ref.country` phone plan) or compliance packs, never `if (country == …)`.
5. **Redis is never a system of record.**
6. **No ORM:** named SQL via `JdbcClient` (ADR-013).
7. **Migrations** are expand → migrate → contract across all shard schemas. The first statement of each shard migration takes the advisory lock.
8. **PII:** a phone number never appears in logs, events, URLs or `toString()`; names are masked per clearance (SPEC-GRW-01 R22).
9. **Configuration only from environment variables** (SPEC-PLAT-06): every variable is documented in `.env.example`; `ConfigurationHygieneTest` guards it.
10. **Spec-driven development:** spec → parameterized test rows named after spec example IDs → code → green.
11. **Reporting:** run `mvn -B verify` before claiming success.
12. **Git workflow:** never commit to `main`; branch `<type>/<name>`; PR body with `Spec: docs/specs/...`; squash-merge when CI, policy and Claude review are green.
